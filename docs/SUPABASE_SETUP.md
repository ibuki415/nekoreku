# Supabase（クラウド）の設定手順

ネコレク のクラウド機能（ログイン・みんなの猫を地図で見る・コレクト）を使うための設定です。
**設定しなくてもアプリは動きます**（猫がこの端末の中だけに保存される「端末内モード」）。
所要時間は 15 分ほど。無料プランで足ります。

## 1. プロジェクトを作る

1. https://supabase.com を開き、「Start your project」からサインアップ（GitHub アカウントでも可）。
2. ログイン後、「New project」を押す。
3. 次を入れて「Create new project」を押す。
   - **Name**: `nekoreku` など好きな名前
   - **Database Password**: 自動生成のままで OK（どこかにメモ。普段は使いません）
   - **Region**: `Northeast Asia (Tokyo)`
4. 数分待つと、ダッシュボードが開きます。

## 2. テーブルなどを作る（SQL を実行）

1. 左メニューの **SQL Editor** を開く。
2. 「New query」を押す。
3. このリポジトリの `supabase/schema.sql` を開き、**中身を全部コピー**して貼り付ける。
4. 右下の **Run** を押す。「Success. No rows returned」と出れば成功です。
   - 何度実行しても壊れない作りなので、エラーが出たらそのまま再実行して大丈夫です。
5. 左メニューの **Table Editor** に `profiles` / `cats` / `collections` が、**Storage** に `cat-stickers` が増えていれば OK。

## 3. メールログインを有効にする

1. 左メニューの **Authentication** → **Sign In / Providers**（古い画面では「Providers」）を開く。
2. **Email** を開き、有効（Enable）になっていることを確認する。
   - 「Confirm email」はオンのままで OK。
3. 一度に送れるメール数には制限があります（無料枠の標準メールは 1 時間に数通）。試すときは何度も送らないでください。

## 4. メールに「6桁のコード」を入れる（大事）

ネコレク はメールのリンクではなく **6桁のコード** でログインします。初期のメール文面にはコードが入っていないので、書き換えます。

1. **Authentication** → **Emails**（古い画面では「Email Templates」）を開く。
2. **Magic Link** のテンプレートを開く。
   - 初めてログインする人には **Confirm sign up** のテンプレートが使われることがあります。**両方** を同じように直してください。
3. 本文に `{{ .Token }}` を入れる。例:

   ```html
   <h2>ネコレクのログインコード</h2>
   <p>アプリに次の6桁の数字を入力してください。</p>
   <p style="font-size:28px;font-weight:bold;letter-spacing:6px">{{ .Token }}</p>
   ```

4. **Save** を押す。

> コードの桁数は **Authentication → Sign In / Providers → Email** の「OTP length」で変えられます。ネコレク は 6 桁前提なので、6 のままにしてください。

## 5. キーを `.env.local` に書く

1. 左メニュー下の **Project Settings**（歯車）→ **API**（または「API Keys」）を開く。
2. 次の 2 つをコピーする。
   - **Project URL**（`https://xxxxxxxx.supabase.co`）
   - **anon（publishable）key**（`anon` / `public` と書かれた長い文字列。`service_role` や secret は **絶対に使わない**）
3. このリポジトリの `.env.local.example` を `.env.local` という名前でコピーし、値を書き換える。

   ```
   NEXT_PUBLIC_SUPABASE_URL=https://あなたのプロジェクト.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=コピーしたanonキー
   ```

   `.env.local` は Git に入らない設定になっています。他人に見せたり、チャットに貼ったりしないでください。

## 6. 開発サーバーを再起動する

環境変数は起動時に読み込まれるので、`npm run dev` を一度止めて（Ctrl+C）、もう一度起動します。

## 7. 動作確認

1. アプリの **マイページ** タブを開く。「ログイン」の入力欄が出ていれば設定成功です（出ないときは「クラウド機能は未設定です」と表示されます）。
2. メールアドレスを入れて「コードを送る」→ メールの 6 桁を入力 →「ログイン」。
3. ログインできたら、猫を撮るとクラウドにも自動で保存されます。すでに撮ってある猫は、マイページの「端末内の猫をクラウドに保存」で送れます。
4. 別の端末で同じメールでログインし、「クラウドから取り込む」で自分の猫を呼び戻せます。

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 「未設定です」のまま | `.env.local` の名前と場所（`package.json` と同じ階層）、変数名の綴り、dev の再起動 |
| メールが来ない | 迷惑メールフォルダ。送信回数の制限（しばらく待つ）。Email プロバイダが有効か |
| メールにコードが無い（リンクだけ） | 手順 4 のテンプレートに `{{ .Token }}` を入れたか（Magic Link と Confirm sign up の両方） |
| 「コードが違うか期限切れ」 | 新しいメールのコードを使う（再送すると古いコードは無効）。時間をおきすぎない |
| 猫の保存に失敗する | 手順 2 の SQL が最後まで成功したか。Storage に `cat-stickers` があるか |

## 補足：プライバシーについて

- 撮影場所の**正確な座標は端末の中だけ**に保存されます。クラウドには小数第 2 位（約 1 km 四方）に丸めた値だけが送られ、サーバー側でも丸めて保存します。
- 猫の画像は公開バケットに置かれるため、画像の URL を知っている人は見られます。
- クラウドの猫は、ログインしているユーザーなら誰でも一覧・閲覧できます。
